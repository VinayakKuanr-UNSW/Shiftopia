# shift_events Event-Envelope Enrichment

Adds an additive "event envelope" to the immutable `public.shift_events` ledger so
analytics (Agent B's KPI RPC) can slice by **who acted**, **which domain** an event
belongs to, and **which assignment attempt (episode)** it falls in — without
re-deriving these from `event_type` / `metadata` on every read.

Everything here is **additive and decoupled**: it does NOT modify the gateway
(`sm_apply_shift_op`), the capture trigger (`fn_capture_shift_event`), the validator
(`fn_validate_shift_event`), or the episode view (`v_shift_assignment_episodes`).

---

## Apply order

| # | File | Purpose |
|---|------|---------|
| 1 | `20260626090000_shift_events_envelope.sql` | `ADD COLUMN IF NOT EXISTS` the 7 envelope columns + 3 indexes + `COMMENT`s. Idempotent. |
| 2 | `20260626090050_shift_events_envelope_backfill.sql` | One-time history fill of `domain`, `actor_role`, `idempotency_key`, `shift_version`, `episode_seq`. Re-runnable (every UPDATE is `WHERE <col> IS NULL`). |
| 3 | `20260626090100_shift_events_enrich_trigger.sql` | `fn_enrich_shift_event()` BEFORE INSERT trigger that fills-if-null the cheap columns on every new event. |

The timestamp prefixes guarantee 1 → 2 → 3 ordering. Run them in that order.

> `actor_id` already exists (migration `20260621100000_shift_events_actor.sql`) and is
> **not** part of this work. `actor_id` = who PERFORMED the event; `employee_id` = who
> it is ABOUT; `actor_role` (new) = the *role* of that actor.

## Columns added (all nullable)

| Column | Type | Source | Notes |
|--------|------|--------|-------|
| `actor_role` | `text` | event_type heuristic | `'manager'` \| `'employee'` \| `'system'`. **Approximate** (see below). |
| `domain` | `text` | event_type map | `'shift'` \| `'assignment'` \| `'offer'` \| `'trade'`. Deterministic. |
| `episode_seq` | `integer` | per-shift gaps-and-islands | 1-based attempt number; NULL before the first opening event. |
| `correlation_id` | `uuid` | (future write paths) | Saga/workflow grouping. Not backfilled. |
| `causation_id` | `uuid` | (future write paths) | Event-causation chain. Not backfilled. |
| `idempotency_key` | `uuid` | `metadata->>'idem'` | Gateway-stamped idempotency uuid. |
| `shift_version` | `integer` | `metadata->>'to_version'` | `shift.version` AFTER the op. |

### Indexes

- `idx_shift_events_actor_time` `(actor_id, event_time)` — actor activity feeds.
- `idx_shift_events_domain_type_time` `(domain, event_type, event_time)` — KPI domain+type windows.
- `idx_shift_events_shift_episode` `(shift_id, episode_seq)` — events for one attempt of a shift.

## Mapping 1 — `domain` (DETERMINISTIC, authoritative)

`event_type` fully determines the bucket:

| domain | event_type |
|--------|-----------|
| `offer` | `OFFERED`, `ACCEPTED`, `REJECTED`, `IGNORED` |
| `assignment` | `ASSIGNED`, `UNASSIGNED`, `EMERGENCY_ASSIGNED`, `CANCELLED`, `LATE_CANCELLED`, `NO_SHOW`, `CHECKED_IN`, `LATE_IN`, `EARLY_OUT` |
| `trade` | `SWAPPED_IN`, `SWAPPED_OUT` |
| `shift` | `OP_APPLIED` and any other/future type (catch-all) |

Used identically in the backfill (statement 1) and the enrich trigger.

## Mapping 2 — `actor_role` (⚠️ APPROXIMATE BACKFILL HEURISTIC)

The historical ledger predates explicit actor stamping, so role is **inferred** from
`event_type`. This is a best-effort guess, **not** authoritative provenance:

| actor_role | event_type | rationale |
|------------|-----------|-----------|
| `manager` | `ASSIGNED`, `EMERGENCY_ASSIGNED`, `OFFERED`, `UNASSIGNED` | manager/admin-initiated |
| `employee` | `ACCEPTED`, `REJECTED`, `CANCELLED`, `LATE_CANCELLED`, `SWAPPED_OUT`, `SWAPPED_IN`, `CHECKED_IN`, `LATE_IN`, `EARLY_OUT` | worker-initiated |
| `system` | `IGNORED`, `NO_SHOW`, `OP_APPLIED` | automatic / ambiguous |

> **Caveats:** `OFFERED` can be auto-generated by an auto-assign engine (we still tag
> `manager`); `SWAPPED_IN`/`SWAPPED_OUT` could be manager-forced (we tag `employee`).
> New write paths SHOULD set `actor_role` explicitly. The enrich trigger and the
> backfill both fill **only when NULL**, so an explicit value always wins.

`OP_APPLIED` is the gateway's neutral audit `shift_event_type` value (minted in
`20260621100050_shift_event_op_applied_enum.sql`). It maps to `domain = 'shift'`,
`actor_role = 'system'`.

## `episode_seq` derivation (parity with the view)

`episode_seq` is the **per-event** attempt number. The backfill computes it with a CTE
that is a **verbatim copy** of the boundary CTEs in
`20260624090000_shift_assignment_episodes.sql`:

```
ordered_events   -- per-shift events WHERE employee_id IS NOT NULL
classified       -- tag opening (ASSIGNED/OFFERED/EMERGENCY_ASSIGNED/SWAPPED_IN)
                 --     & closing (REJECTED/IGNORED/CANCELLED/LATE_CANCELLED/
                 --                SWAPPED_OUT/NO_SHOW/UNASSIGNED) types
boundary_events  -- LAG over OPENING/CLOSING events only
boundary_starts  -- new episode at: first holder | re-open after close | holder change
episode_assigned -- cumulative SUM of start-markers over ALL events (intra = 0)
```

The per-event `episode_seq` is exactly the value the view produces in its
`episode_assigned` CTE *before* its `GROUP BY`. The backfill joins that value back to
`shift_events` by event id.

**Parity rules baked in:**

- `ordered_events` filters `employee_id IS NOT NULL` (identical to the view). Events
  with NULL `employee_id` (e.g. `OP_APPLIED` audit rows, subject-less `UNASSIGNED`)
  are not in the CTE and **keep `episode_seq = NULL`** — matching the view, which
  never assigns them an episode.
- The view excludes `episode_seq = 0` (events before the first opening) from
  aggregation; we write `NULL` for those rows via `NULLIF(seq, 0)`.
- Ordering tiebreaks `(event_time, event_id)` are reproduced verbatim, so the
  cumulative sum lands on identical boundaries.

**Residual parity risk:** none on the seq value — the CTEs are a literal copy. The
risk is **drift**: this block is a *copy*, not a call. If the view's boundary CTEs are
ever edited, the backfill's CTE **must be updated in lockstep**. The enrich trigger
does **not** compute `episode_seq` (a single-row BEFORE trigger cannot see per-shift
history); new rows get `episode_seq` on the next run of the backfill / an offline
recompute. This is a documented limitation, not a bug.

---

## Trigger interaction (verified)

- **BEFORE INSERT:** baseline `trg_validate_shift_event` also runs. PostgreSQL fires
  per-row BEFORE triggers in trigger-name order; `trg_enrich_shift_event` sorts first.
  Enrich only sets envelope columns (never `employee_id`/`event_type`), so order does
  not affect validation either way.
- **AFTER INSERT:** `trg_refresh_snapshots` reads the
  `v_shift_assignment_episodes` *view*, not the `episode_seq` *column*, so a NULL
  `episode_seq` at insert time does not affect snapshot projection.
- `fn_capture_shift_event` is a trigger on `public.shifts` (not `shift_events`) and is
  unaffected.

## Validation queries

Run after applying all three migrations.

```sql
-- 1. No row should be missing domain/actor_role (both are total maps).
SELECT count(*) AS missing_envelope
FROM public.shift_events
WHERE domain IS NULL OR actor_role IS NULL;
-- expect 0

-- 2. domain distribution sanity.
SELECT domain, count(*) FROM public.shift_events GROUP BY domain ORDER BY domain;

-- 3. actor_role distribution sanity.
SELECT actor_role, count(*) FROM public.shift_events GROUP BY actor_role ORDER BY actor_role;

-- 4. domain<->event_type map is consistent (should return ZERO mismatches).
SELECT event_type, domain, count(*)
FROM public.shift_events
WHERE domain <> CASE event_type
        WHEN 'OFFERED' THEN 'offer' WHEN 'ACCEPTED' THEN 'offer'
        WHEN 'REJECTED' THEN 'offer' WHEN 'IGNORED' THEN 'offer'
        WHEN 'ASSIGNED' THEN 'assignment' WHEN 'UNASSIGNED' THEN 'assignment'
        WHEN 'EMERGENCY_ASSIGNED' THEN 'assignment' WHEN 'CANCELLED' THEN 'assignment'
        WHEN 'LATE_CANCELLED' THEN 'assignment' WHEN 'NO_SHOW' THEN 'assignment'
        WHEN 'CHECKED_IN' THEN 'assignment' WHEN 'LATE_IN' THEN 'assignment'
        WHEN 'EARLY_OUT' THEN 'assignment'
        WHEN 'SWAPPED_IN' THEN 'trade' WHEN 'SWAPPED_OUT' THEN 'trade'
        ELSE 'shift' END
GROUP BY event_type, domain;
-- expect 0 rows

-- 5. idempotency_key / shift_version backfilled wherever the metadata carried them.
SELECT
  count(*) FILTER (WHERE metadata ? 'idem'        AND idempotency_key IS NULL) AS missing_idem,
  count(*) FILTER (WHERE metadata ? 'to_version'  AND shift_version   IS NULL) AS missing_ver
FROM public.shift_events;
-- expect 0 / 0  (modulo rows whose metadata value is malformed and intentionally skipped)

-- 6. episode_seq PARITY: per-event seq on the ledger must equal the view's
--    episode_assigned value. This recomputes the view's pre-GROUP-BY seq and
--    diffs it against the column. Expect ZERO mismatches.
WITH ordered_events AS (
    SELECT se.id AS event_id, se.shift_id, se.employee_id, se.event_type, se.event_time
    FROM public.shift_events se WHERE se.employee_id IS NOT NULL
),
classified AS (
    SELECT oe.*,
        (oe.event_type IN ('ASSIGNED','OFFERED','EMERGENCY_ASSIGNED','SWAPPED_IN')) AS is_opening_type,
        (oe.event_type IN ('REJECTED','IGNORED','CANCELLED','LATE_CANCELLED','SWAPPED_OUT','NO_SHOW','UNASSIGNED')) AS is_closing_type
    FROM ordered_events oe
),
boundary_events AS (
    SELECT c.shift_id, c.event_id, c.event_time, c.employee_id, c.is_opening_type,
        LAG(c.is_closing_type) OVER w AS prev_boundary_was_closing,
        LAG(c.employee_id)     OVER w AS prev_boundary_employee
    FROM classified c WHERE c.is_opening_type OR c.is_closing_type
    WINDOW w AS (PARTITION BY c.shift_id ORDER BY c.event_time, c.event_id)
),
boundary_starts AS (
    SELECT be.shift_id, be.event_id,
        CASE WHEN be.is_opening_type AND (
            be.prev_boundary_employee IS NULL OR be.prev_boundary_was_closing
            OR be.employee_id IS DISTINCT FROM be.prev_boundary_employee) THEN 1 ELSE 0 END AS starts_new_episode
    FROM boundary_events be
),
episode_assigned AS (
    SELECT c.event_id,
        SUM(COALESCE(bs.starts_new_episode, 0)) OVER (
            PARTITION BY c.shift_id ORDER BY c.event_time, c.event_id
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS episode_seq
    FROM classified c
    LEFT JOIN boundary_starts bs ON bs.shift_id = c.shift_id AND bs.event_id = c.event_id
)
SELECT count(*) AS episode_seq_mismatches
FROM public.shift_events se
JOIN episode_assigned ea ON ea.event_id = se.id
WHERE se.episode_seq IS DISTINCT FROM NULLIF(ea.episode_seq, 0);
-- expect 0
```
